# Starrypad iOS

A drum pad for iPhone and iPad, built to be played with a class-compliant USB
MIDI controller plugged straight into the device — or with your fingers, where
the pad reads velocity from how high up you hit it.

Sixteen pads, a bar-length looper, and a 27-sample TR-808 kit that ships in the
app. No account, no network, no file pickers.

## Why it exists separately

The desktop app it grew out of lives at
[purinzan/native-usb-drum-pad](https://github.com/purinzan/native-usb-drum-pad).
Only about 7% of that codebase is platform-independent, so this is a rewrite in
Swift rather than a port, and it belongs in its own repository.

What is shared is the thinking, not the code: the velocity curve, the floor
expansion for controllers whose softest hit is 50, the layer velocity splits and
the colour tokens all come from the desktop app and are commented where they
land here, so the two can be compared without being coupled.

## Building

Requires Xcode and [xcodegen](https://github.com/yonaskolb/XcodeGen)
(`brew install xcodegen`). The `.xcodeproj` is generated, not committed.

```bash
xcodegen generate
open Starrypad.xcodeproj
```

To run on a device from the command line, set `DEVELOPMENT_TEAM` in
`project.yml` to your own team, then:

```bash
xcodebuild -project Starrypad.xcodeproj -scheme Starrypad -configuration Debug \
  -destination "platform=iOS,id=<device-udid>" -allowProvisioningUpdates build
```

The first launch on a device needs the developer profile trusted once, under
Settings → General → VPN & Device Management.

### One thing to check after touching `project.yml`

Samples are declared in `sources:` with `buildPhase: resources`. A target has no
`resources:` key — xcodegen ignores one silently, the build still succeeds, and
the app ships with an empty bundle. That failure is invisible until the app runs
and makes no sound, so check the count rather than the build result:

```bash
ls build/Build/Products/*/Starrypad.app/*.wav | wc -l   # expect 27
```

## Connecting a controller

Any class-compliant USB MIDI controller works. On a USB-C device, connect it
directly or through a USB-C adapter; on Lightning, use the Camera Adapter.

The port name appears in the header in teal once the device is seen. Beside it,
the last note number received and which mapping answered it — because a cable
that is plugged in and silent should be diagnosable from the phone.

Notes are resolved in three steps, so no hit is ever dropped:

1. the kit's own note table, matching the desktop app
2. the two blocks a 4×4 controller usually sends: General MIDI from 36, the
   lower block from 20
3. anything still unrecognised takes the next pad, in the order it arrives

Bus-powered controllers can draw more than a phone will supply. If the port name
never appears, try a powered USB hub.

## The looper

`Rec` starts the clock and records. Pressing it again drops out of record and
keeps the loop running, so overdubbing is one button. `Play` is what stops.
Events are stored as beat positions rather than seconds, so tempo can move
without rewriting what you played, and playback goes through the same path a
finger takes — a loop cannot record itself.
